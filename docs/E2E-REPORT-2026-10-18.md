### CLI and local app

**B1 (P2). The app goes stale after `variantly keep` / `variantly clean` from the terminal, and then shows raw git errors.**
The running app keeps its own copy of the run; the CLI writes the state file
behind its back and nothing tells the app (no lock, no reload).
1. `npx variantly --demo --no-open`, make 3 variants, wait until ready.
2. In another terminal: `npx variantly keep 1 --no-rollout` (or `clean`).
3. The app still says the run is ready and offers **Keep** on every variant;
   `GET /api/state` still returns `phase: "ready"` while the state file says
   `finalized` (or is gone).
4. Keep another variant in the app. After `clean`:
   `git diff --binary <base> variantly/…/v1 failed (exit 128) fatal: ambiguous argument …`.
   After `keep 1`: `git apply failed: error: style.css: does not match index`.
Nothing is lost (the second apply is refused), but the user sees git
internals. Suggest: the CLI commands refuse (or hand off to the app over
its API) while an app is running for the repo, or the app watches the state
file.

**B2 (P2, fixed in #149). Compare › Phone › Side by side renders each variant ~195px wide.**
The phone frame (390px) was split in two, so each side was a 194/195px
iframe, narrower than any phone, with a horizontal scrollbar in the
variant. Screenshot `app-14-phone-side-dark.png`; fixed:
`fix-phone-side-desktop.png` (390 + 390).

**B3 (P2, fixed in #149). On a 390px phone the app is wider than the screen while a run is going or kept.**

`fix-dark-06-board.png`.

**B5 (P3). `--agent claude --yes` with no `claude` on PATH starts anyway and fails with `spawn claude ENOENT`.**
`PATH=<node,git,npx only> npx variantly --agent claude --yes --count 2 --no-open`
prints "Generating 2 variants with claude…" and nothing else; the terminal
never reports the failure. The app does show it on both variants
(`app-31-agent-missing.png`, "Failed: Could not start claude: spawn claude
ENOENT", Retry offered), so the requirement "the error shows in the app" is
met. But the message is Node jargon with no fix, while a mix (`--agents`)
would have been refused up front with "Claude Code isn't installed (npm
install -g @anthropic-ai/claude-code)", and the wizard marks the card "Not
installed". `assertAgentsReady` only checks mixes by design
("one agent alone keeps today's behaviour"); worth applying the
installed check to a single agent too, and printing the failure in the
terminal on `--yes`.

**B6 (P3). The theme only follows the OS at page load.**

Reloading also drops the wizard back to step 1 (answers are kept).

### Marketing site

**S1 (P2). Concept switches into Candy 3D, Liquid Glass, Inflated Chrome and Sticker Bomb take 5.5–11 s.**
Measured from the `]` keypress to the new concept painted (`html[data-variant]`
changed and `data-swapping` gone), desktop, first visit to each concept,
on the final build (`0a4c1d2`, load average ~10–13 on 4 cores):
f→**g** 11.0 s / 6.6 s (light / dark), h→**i** 8.6 / 5.6 s, k→**l** 6.6 /
6.8 s, p→**q** 6.4 / 9.6 s. Every other switch is 0.8–2.5 s. The same four
were slowest in the earlier sweep too, and a video of `?v=a` then `]`
showed ~7.8 s from keypress to the new title. On #131 (load average 30+)
the median switch was 4–6 s and `?perf=low` was not faster (2.4–7.2 s). The
`setVariant` prefetch race is capped at 400 ms, so the time goes into the
main thread after the swap starts (shader compile / scene build for the 3D
concepts). The author's ~15 s fits these four on a loaded machine.
Suggest: warm the next concept's scene on idle (`prefetchConcept(next, true)`
after the current one settles) and let the view transition start before the
scene is built.

**S2 (P2). The 3D title sometimes draws the "t" at about half size.**
Seen 3 times in 80 sweep screenshots, never on a single fresh load:
`sweep-s-d-light.png` (crop `tiny-t-s.png`), `stale/sweep-n-d-light.png`,
`stale/sweep-p-d-dark.png`. The other letters are full size; the `t` glyph
data is fine in every `public/fonts/3d/*.json` (t/l height ratio 0.83–1.03),
so it looks like a letter left mid-animation (the intro drop / morph) when
the page is busy. Intermittent; repro is "load concepts one after another
in one tab on a loaded machine".

concept (48 on Kinetic Type), 0–3 in dark except Riso, Amber, Brutal Zine,
Bauhaus, Cut & Paste, Dither and Swiss Punk (19–23). They are almost all

  `#f8d7c6`), 3.81:1 on Kinetic Type; in dark, `text-surface/55` numbers at
  1.9–2.7:1;
- run toggle "Classic 20 redesigns": 2.47:1, its "20 redesigns" line 1.89:1;
- the score delta "+13": 2.19:1;
- the "YOU PICK." accent: 2.27:1 at 45pt (Soft Clay light); "SAFETY" h1 on
  /safety light: 2.35:1;

  `aria-hidden` if decorative.
Lighthouse (repo `audit-runner`, home): **Performance 57, Accessibility 96,
Best practices 100, SEO 100**; TBT 18 s and TTI 24.6 s under 4x CPU

**S6 (P3). BranchLog opens with three clicks but not with three taps.**
Desktop: triple-click the footer stamp "VARIANT RECORD VY-0A4C1D2 · LOGGED
2026-10-18" → "BRANCH LOG" dialog, Esc closes, focus returns to the stamp.
Phone (390x844, touch): three taps 150–200 ms apart register three clicks
but no dialog opens; three clicks 50 ms apart in the same page do. The
650 ms window is tight for taps (each tap here takes ~200 ms), or the press
timestamps are reset by the tap's pointer events. `feat-m-branchlog.png`.

**S7 (P3). After client-side navigation the previous page stays in the DOM, so IDs repeat.**
With `cacheComponents: true`, navigating / → /docs keeps the old page
(hidden, 0px tall) with its own `<header>`, `#site-menu`, `#content` and a
second `nav[aria-label=Main]`. The visible copy comes first so nothing
breaks today (menu, skip link and `getElementById` resolve to it), but
validators and any `document.querySelector('#…')` that hits the hidden copy
will misbehave.

**S8 (P3). The title canvas's pixel ratio isn't clamped after a resize.**
Phone (DPR 3): on load the 3D title canvas is 780x394 for 390x197 CSS px
(ratio 2); after rotating to landscape and back it is 1170x591 (ratio 3).
2.25x the pixels on the device least able to afford it. Resizing itself is
fine: no blank frames 150 ms after rotation, canvases match the new size,
no errors (Soft Clay, Candy 3D, Inflated Chrome).

**S9 (P3). Smaller things.**
- Inflated Chrome on phones: the HUD text ("1/20 INFLATED CHROME METALNESS
  1.00 ROUGH 0.05") overlaps the title's V.
- Stone & Linen on phones: the title is small and the headline starts below
  the fold.
- Uncanny Mirror and Liquid Glass (light): the 3D title is pale on pale.
- `next build` warns on `::highlight(vy-untyped)` (globals.css): Lightning
  CSS doesn't know the pseudo-element. The rule ships, but the warning hides
  real ones.
- Incremental `next build` after merging main served **stale CSS** (no
  `.vy-menu`, `.vy-burger`, `.vy-tip` rules), which made the phone menu
  render open on every page. A clean build (`rm -rf .next`) fixed it, so
  this is a local Turbopack cache hazard, not a site bug; worth knowing
  before trusting a local build after a big merge.
- `/favicon.ico` is 404 (the page links `/icon.svg`, so browsers are fine).
